
## 第一部分：CSV（**主战场，永远先学透**）

### 1.1 基本读写

```python
import pandas as pd

df = pd.DataFrame({"age":[20,30,40,10], "name":["张三","李四","王五","赵六"], "id":[101,102,103,104]})
df.set_index("id", inplace=True)

# 导出
df.to_csv("data/test.csv", encoding="gbk")

# 导入
df = pd.read_csv("data/test.csv", encoding="gbk")
```

### 1.2 `encoding` 编码问题（**中文必踩坑**）

| 编码 | 何时用 | 例子 |
|---|---|---|
| `utf-8`（默认） | 全英文 / Mac / Linux | `encoding="utf-8"` |
| `utf-8-sig` | 给 Windows Excel 看的（带 BOM）| `encoding="utf-8-sig"` |
| `gbk` | Windows 中文老系统 | `encoding="gbk"` |

🔥 **第一卡点（实战必撞）**：

```python
df.to_csv("test.csv")              # 默认 utf-8 写入
# Windows 用 Excel 打开 → 中文乱码！

df.to_csv("test.csv", encoding="utf-8-sig")  # ✅ 给 Excel 看
df.to_csv("test.csv", encoding="gbk")         # ✅ 老 Windows 系统
```

**记忆**：

- 数据要给 **Excel 看** → `utf-8-sig`
- 数据要给 **Python / Mac** 看 → `utf-8`
- 上游来的 **老 CSV 中文** 读不出来 → 尝试 `gbk`

### 1.3 常用参数（**远不止 encoding**）

```python
pd.read_csv(
    "test.csv",
    encoding="utf-8",        # 编码
    sep=",",                 # 分隔符（TSV 用 \t）
    header=0,                # 第几行做表头（None = 没表头）
    index_col=0,             # 哪一列当 index（默认不当）
    usecols=["id","age"],    # 只读这几列
    nrows=1000,              # 只读前 N 行（**大文件预览必备**）
    skiprows=2,              # 跳过前 2 行
    na_values=["?", "-"],    # 把这些值视为 NaN
    dtype={"id": int, "age": "Int64"},  # 强制列的类型
    parse_dates=["date"]     # 哪些列自动转日期
)
```

🔥 **第二卡点**：默认 `index_col` **不设置**——所以 `read_csv` 出来会多一列"Unnamed: 0"（如果你导出时带了 index）。

**两种避免方式**：

```python
# 方式 A：导出时不带 index
df.to_csv("test.csv", index=False)

# 方式 B：读取时指定 index_col
df = pd.read_csv("test.csv", index_col=0)
```

### 1.4 大文件分块读取（**了解即可**）

```python
# 不想一次性把 1GB 的 CSV 读进内存
for chunk in pd.read_csv("huge.csv", chunksize=10000):
    process(chunk)            # chunk 是 10000 行的 DataFrame
```

视频里没讲，但**实战遇到 GB 级 CSV 时这是唯一答案**。

## 第二部分：JSON

### 2.1 基本读写

```python
df.to_json("data/test.json", force_ascii=False)
df = pd.read_json("data/test.json")
```

### 2.2 `force_ascii=False` —— 中文不变 `\uXXXX`

**默认行为**（`force_ascii=True`）：

```json
{"name": "张三", "age": 20}
```

**指定 `force_ascii=False`**：

```json
{"name": "张三", "age": 20}
```

→ 第二种**人能看懂**，**永远加 `force_ascii=False`**。

### 2.3 JSON 的 5 种排列方式

JSON 有多种"行列布局"，导出/导入要对得上：

```python
df.to_json("test.json", orient="records")   # [{...}, {...}]   ← API 最常用
df.to_json("test.json", orient="columns")   # {col1:{0:x,1:y}, col2:{...}}  ← 默认
df.to_json("test.json", orient="index")     # {0:{col1:x,col2:y}, 1:{...}}
df.to_json("test.json", orient="split")     # {columns:[...], data:[[...]], index:[...]}
df.to_json("test.json", orient="values")    # [[x,y], [x,y]]   ← 无列名
```

**实战 90% 用 `orient="records"`**——前后端约定的标准格式。

```python
pd.read_json("api_response.json", orient="records")
```

## 第三部分：剪贴板（**演示 / 临时用**）

```python
df.to_clipboard()                 # 复制到剪贴板
```

**使用场景**：从 Excel / 网页表格 **复制一段** → `pd.read_clipboard()` 直接变 DataFrame。**调试时神器**，正式代码里不要用。

## 第四部分：MySQL（**接业务库的标准接口**）

### 4.1 环境准备

```bash
# 装两个包
pip install sqlalchemy pymysql
```

`sqlalchemy` 提供"统一的数据库接口"，`pymysql` 是 MySQL 的具体驱动。

### 4.2 创建连接（**engine 是核心对象**）

```python
from sqlalchemy import create_engine

host    = "localhost"
port    = 3306
user    = "root"
passwd  = "123456"
db      = "atguigu"
charset = "utf8mb4"

engine = create_engine(
    f"mysql+pymysql://{user}:{passwd}@{host}:{port}/{db}?charset={charset}"
)
```

**解读这个 URL**（字符串拼出来的"连接信息"）：

```
mysql+pymysql:// root : 123456 @ localhost : 3306 / atguigu ? charset=utf8mb4
↑      ↑          ↑     ↑          ↑           ↑       ↑              ↑
方言   驱动      用户  密码        主机        端口   数据库名       字符集
```

🔥 **第三卡点**：`utf8mb4` 不是写错的——这是 MySQL 支持 **完整 4 字节 UTF-8**（含 emoji 等）的字符集。`utf8` 在 MySQL 里只有 3 字节，存表情会丢字符。**永远用 `utf8mb4`**。

### 4.3 导出到 MySQL（`to_sql`）

```python
df.to_sql(
    "t_test",                # 表名
    engine,                  # 连接引擎
    if_exists="replace"      # 表已存在时的策略
)
```

`if_exists` 三种选项：

| 值 | 含义 |
|---|---|
| `"fail"` | 表已存在 → 报错（默认）|
| `"replace"` | 删表重建 |
| `"append"` | 在已有表后追加 |

**何时用哪个**：

- 调试 / 重新生成 → `"replace"`
- 日常增量数据 → `"append"`
- 防止误覆盖 → `"fail"`

### 4.4 从 MySQL 读（`read_sql`）

```python
# 方式 A：直接读整张表
df = pd.read_sql("t_test", engine)

# 方式 B：写 SQL 查询（**实战更常用**）
df = pd.read_sql(
    "SELECT id, name, salary FROM employees WHERE department_id = 80",
    engine
)
```

🔥 **方式 B 是真实业务的标准动作**——直接用 SQL 在数据库里过滤，**只把需要的那部分数据拉到 Pandas 内存**。不要 `SELECT *` 然后在 Python 里筛——慢、爆内存。

### 4.5 iOS 老兵的视角

```swift
// Swift 里访问数据库要这样：
let connection = try MySQLConnection.connect(...)
let rows = try connection.query("SELECT ...").wait()
let users = rows.map { row in
    User(id: row.column("id").int, name: row.column("name").string)
}
// 一串繁琐的"行 → 对象"映射
```

```python
# Pandas 一行
df = pd.read_sql("SELECT * FROM users", engine)
```

**这是 Pandas 替代后端代码的关键场景**——数据分析师不需要写 model 映射，**直接拿到一张表就能分析**。

## 第五部分：其他常见格式（视频没讲但要知道）

```python
# Excel
df.to_excel("test.xlsx", sheet_name="Sheet1", index=False)
pd.read_excel("test.xlsx", sheet_name="Sheet1")

# Parquet（大数据列存储，**比 CSV 快 10 倍**）
df.to_parquet("test.parquet")
pd.read_parquet("test.parquet")

# Pickle（Python 专属二进制，**最快但只 Python 能读**）
df.to_pickle("test.pkl")
pd.read_pickle("test.pkl")

# HTML 表格（**爬虫神器**：直接从网页扒表格）
tables = pd.read_html("https://en.wikipedia.org/wiki/...")
df = tables[0]   # 第一张表
```

| 格式 | 速度 | 跨语言 | 何时用 |
|---|---|---|---|
| **CSV** | 慢 | ✅ | 主战场，通用 |
| **JSON** | 中 | ✅ | 接 API |
| **Excel** | 慢 | ✅ | 给非技术人员看 |
| **Parquet** | **快** | ✅ | 大数据场景首选 |
| **Pickle** | **最快** | ❌ | 只 Python 用、临时缓存 |
| **HTML** | 慢 | ✅ | 爬网页表格 |

---

## 性能 / 数据量 对照

```
~1 万行     CSV / JSON 都够用
~10 万行    CSV 开始变慢（10s+），考虑 Parquet
~100 万行   必须用 Parquet / SQL / 分块读
~1000 万+   想都别想 CSV，直接 Spark / DuckDB
```

## 卡点汇总（4 大坑预警）

1. **CSV 中文乱码** —— Mac 用 `utf-8`，Windows Excel 用 `utf-8-sig`，老系统用 `gbk`
2. **导出带 index 但导入没识别** —— 出现 "Unnamed: 0" 列。导出加 `index=False` 或导入加 `index_col=0`
3. **JSON 中文变 `\uXXXX`** —— 永远加 `force_ascii=False`
4. **MySQL 字符集别写 `utf8`** —— 用 `utf8mb4`，否则 emoji 丢字符
