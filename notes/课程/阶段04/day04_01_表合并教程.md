## 为什么需要表合并？

真实工作里，**数据永远散在多张表里**——不是一张大表。

举个 iOS 开发者熟的例子：

```
users 表 (用户基本信息)             orders 表 (订单记录)
┌──────────────────────┐           ┌─────────────────────────────┐
│ user_id  name   age  │           │ order_id  user_id  amount   │
│ 1        Alice  25   │           │ 101       1        50       │
│ 2        Bob    30   │           │ 102       1        80       │
│ 3        Carol  28   │           │ 103       2        100      │
└──────────────────────┘           │ 104       4        30       │
                                    └─────────────────────────────┘
                                    
"Alice 总共消费了多少？" —— 必须把两张表"拼起来"才能算
"哪些用户从没下过单？"    —— 同样需要合并
"每个用户的平均订单金额？" —— 合并完再 groupby
```

**Pandas 给你三把工具来做这件事**：`concat` / `merge` / `join`。

---

## 一句话定位 3 个工具

```
concat   ── "上下叠 / 左右贴"，按位置硬拼  ← 用 axis 控制方向
merge    ── 按某列共同的值配对拼，类似 SQL JOIN  ← 最常用，最难
join     ── merge 的"按 index 简化版"  ← 极少用
```

| 工具 | 何时用 | 类比 |
|---|---|---|
| `concat` | 同一种数据，**不同来源/批次** | 上下叠：今年 + 去年的销售；左右贴：再加几列 |
| `merge` | **不同种**数据，需要按 key 关联 | SQL 的 JOIN，最常用 |
| `join` | `merge` 的简版，固定按 index | 90% 场景用 merge 更明确 |

**优先级**：**深扎 merge**（重点中的重点）→ 弄懂 concat → join 知道有就行。

## 第一部分：concat —— "上下叠 / 左右贴"

### 1.1 一句话理解

`concat` 把多个 DataFrame **按位置硬拼**——不在乎列名/index 是否对得上，对得上的算同一列、对不上的填 NaN。

### 1.2 两种方向

```python
pd.concat([df1, df2], axis=0)   # 上下叠（默认）—— 行增加
pd.concat([df1, df2], axis=1)   # 左右贴      —— 列增加
```

**`axis` 的含义和 NumPy 完全一致**：
- `axis=0` 是"沿着行的方向（往下）"
- `axis=1` 是"沿着列的方向（往右）"

> 想不清楚的话回去翻 [[numpy轴的理解]]。这里的 `axis` 和 NumPy 是同一套概念。

### 1.3 上下叠（axis=0）

```python
df1 = pd.DataFrame({'A': [1, 2], 'B': [3, 4]})
df2 = pd.DataFrame({'A': [5, 6], 'B': [7, 8]})

pd.concat([df1, df2], axis=0)
```

结果：

```
   A  B
0  1  3       ← df1 第 0 行
1  2  4       ← df1 第 1 行
0  5  7       ← df2 第 0 行（注意 index 是 0！没自动重排）
1  6  8       ← df2 第 1 行（index 是 1）
```

#### 几个常用参数

```python
pd.concat([df1, df2], axis=0,
          ignore_index=True)   # 自动重排 index 成 0,1,2,3
# 否则会出现重复的 0, 1, 0, 1 这种乱 index

pd.concat([df1, df2], axis=0,
          keys=['Q1', 'Q2'])   # 给每个来源加个外层标签
# 用 MultiIndex 区分谁来自 df1/df2
```

### 1.4 左右贴（axis=1）

```python
df1 = pd.DataFrame({'A': [1, 2, 3]}, index=['x', 'y', 'z'])
df2 = pd.DataFrame({'B': [4, 5, 6]}, index=['x', 'y', 'z'])

pd.concat([df1, df2], axis=1)
```

结果：

```
   A  B
x  1  4
y  2  5
z  3  6
```

**注意**：左右贴时，**按 index 对齐**！如果 index 对不上：

```python
df1 = pd.DataFrame({'A': [1, 2]}, index=['x', 'y'])
df2 = pd.DataFrame({'B': [3, 4]}, index=['y', 'z'])

pd.concat([df1, df2], axis=1)
```

结果：

```
     A    B
x  1.0  NaN     ← df2 没有 x，填 NaN
y  2.0  3.0     ← 两边都有 y
z  NaN  4.0     ← df1 没有 z，填 NaN
```

**核心规则**：concat 是按位置硬拼，**index 对不上的不会"自动配对"，缺失就填 NaN**。要按值配对，用 merge。

### 1.5 concat 适用场景

✅ **同结构数据的批次合并**：
- 1 月销售 + 2 月销售 + 3 月销售 → 上下叠
- 多个传感器的同期读数 → 左右贴

❌ **不同结构的关联**（比如 users + orders 按 user_id 关联）→ 用 merge，不要用 concat

## 第二部分：merge —— **数据合并的主力**

> 这一节是 day04 最重要的内容，必须吃透。读 3 遍不为多。

### 2.1 一句话理解

`merge` = **"按某列共同的值"** 把两张表拼起来。等同于 SQL 的 JOIN。

### 2.2 最简单的例子

```python
users = pd.DataFrame({
    'user_id': [1, 2, 3],
    'name': ['Alice', 'Bob', 'Carol']
})

orders = pd.DataFrame({
    'order_id': [101, 102, 103],
    'user_id': [1, 1, 2],
    'amount': [50, 80, 100]
})

# 按 user_id 把两张表合并
users.merge(orders, on='user_id')
```

结果：

```
   user_id   name  order_id  amount
0        1  Alice       101      50
1        1  Alice       102      80
2        2    Bob       103     100
```

**发生了什么**：
- Pandas 拿 users 每一行的 `user_id`，去 orders 里**找匹配的 user_id**
- 找到了就把两张表的列**横着拼起来**变成一行
- Alice (id=1) 在 orders 里有 2 个匹配 → 输出**2 行 Alice**
- Bob (id=2) 在 orders 里有 1 个匹配 → 输出 1 行 Bob
- Carol (id=3) 在 orders 里**没匹配** → **不出现在结果里**（因为默认 inner）

### 2.3 🔥 重头戏：4 种 `how`

这是 day04 最难的概念，也是面试 SQL 必考。**画图理解**：

```
两张表的 user_id 重叠情况：

users:    [1, 2, 3]
orders:   [1, 1, 2, 4]

         users                          orders
       ┌──────┐                       ┌──────┐
       │  3   │                       │  4   │
       │      │ (只在 users)           │      │ (只在 orders)
       ├──────┼─────────┬─────────────┤      │
       │       │ 1, 2  │ (两边都有)    │       │
       └──────┴─────────┴─────────────┴──────┘
```

#### `how='inner'`（默认）—— 只要交集

```python
users.merge(orders, on='user_id', how='inner')
```

**只保留两边都有的 user_id**（即 user_id ∈ {1, 2}）：

```
   user_id   name  order_id  amount
0        1  Alice       101      50
1        1  Alice       102      80
2        2    Bob       103     100
```

3 行（Carol/id=3 被舍弃，id=4 也不出现）。

#### `how='left'`—— **保留左表全部**（最常用）

```python
users.merge(orders, on='user_id', how='left')
```

**保留 users 的所有行**，orders 没匹配的填 NaN：

```
   user_id   name  order_id  amount
0        1  Alice     101.0    50.0
1        1  Alice     102.0    80.0
2        2    Bob     103.0   100.0
3        3  Carol       NaN     NaN     ← Carol 没下过单，订单信息全 NaN
```

**实战中用得最多**——你通常以一张主表为基准，想看"每个主表行有没有附加信息"。

#### `how='right'`—— 保留右表全部

```python
users.merge(orders, on='user_id', how='right')
```

**保留 orders 的所有行**，users 没匹配的填 NaN：

```
   user_id   name  order_id  amount
0        1  Alice       101      50
1        1  Alice       102      80
2        2    Bob       103     100
3        4    NaN       104      30     ← 这个订单的用户 id=4 不在 users 里
```

实战较少用——你完全可以把两张表 swap 后用 `left`。

#### `how='outer'`—— **全保留**

```python
users.merge(orders, on='user_id', how='outer')
```

**两边的 user_id 全部保留**，对方没匹配的填 NaN：

```
   user_id   name  order_id  amount
0        1  Alice     101.0    50.0
1        1  Alice     102.0    80.0
2        2    Bob     103.0   100.0
3        3  Carol       NaN     NaN     ← 只在 users
4        4    NaN     104.0    30.0     ← 只在 orders
```

**实战中用于"想看哪些 id 是单边孤立的"**——数据对账常用。

### 2.4 4 种 how 总览图

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│        users                              orders                 │
│    ┌──────────┐                       ┌──────────┐              │
│    │          │                       │          │              │
│    │   3 ⚫   │          1, 2         │   4 ⚫   │              │
│    │   ⚪     │     ⚫       ⚫       │   ⚪     │              │
│    │          │                       │          │              │
│    └──────────┘                       └──────────┘              │
│                                                                  │
│  inner:         ⚫⚫        (只要交集)                            │
│  left:    🔵🔵 ⚫⚫        (左 + 交集)  ← 最常用                  │
│  right:        ⚫⚫ 🔴🔴   (交集 + 右)                            │
│  outer:   🔵🔵 ⚫⚫ 🔴🔴   (全要)                                 │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

⚫⚫ = 两边都有的 user_id (1, 2)
🔵🔵 = 只在 users 的 (3)
🔴🔴 = 只在 orders 的 (4)
```

**速记口诀**：

- `inner` = 严格匹配 = 短小
- `left/right` = 保某一边 = 偏长
- `outer` = 全要 = 最长

### 2.5 关联列名不同：`left_on` / `right_on`

如果两张表关联列名**不同**：

```python
users = pd.DataFrame({'uid': [1, 2, 3], 'name': ['Alice', 'Bob', 'Carol']})
orders = pd.DataFrame({'customer_id': [1, 2], 'amount': [50, 100]})

users.merge(orders,
            left_on='uid',           # 左表用这一列
            right_on='customer_id')  # 右表用这一列
```

结果两个 key 列都会保留：

```
   uid   name  customer_id  amount
0    1  Alice            1      50
1    2    Bob            2     100
```

**实战提醒**：合并后通常**删掉一个冗余 key 列**：

```python
result = users.merge(orders, left_on='uid', right_on='customer_id')
result = result.drop(columns='customer_id')
```

### 2.6 用 index 关联：`left_index` / `right_index`

```python
users.merge(orders,
            left_index=True,    # 左表用它的 index
            right_index=True)   # 右表用它的 index
```

要么按列、要么按 index、要么混着用——参数自由组合。

## 第三部分：join —— merge 的 "按 index 简版"

```python
df1.join(df2)                       # 默认按 index、how='left'
df1.join(df2, on='key', how='left') # 按列 + 左连接
```

**`join` 和 `merge` 的关系**：

- `join` 默认 `how='left'`，`merge` 默认 `how='inner'`
- `join` 优先用 index，`merge` 优先用列
- 凡是 `join` 能做的，`merge` 都能做

**建议**：以后**优先用 `merge`**，明示比简洁更重要。`join` 你看代码能认出来就行，不用记。

## 第四部分：三者对比 + 选用决策树

```
你想合并两张表，问自己 3 个问题：

Q1: 是"同结构、不同来源"吗？（比如多月数据）
    YES → concat
    NO ↓

Q2: 是"不同结构、按某列关联"吗？（最常见）
    YES → merge
    NO ↓

Q3: 是"按 index 简单关联"吗？（少见）
    YES → join (但 merge 也行)
```

| 场景 | 用哪个 |
|---|---|
| 1 月销售 + 2 月销售 | `concat(axis=0)` |
| 在原表右边再加几列 | `concat(axis=1)` 或 `merge` |
| 用户表 + 订单表关联 | `merge(on='user_id')` |
| 多张表叠 → 再分析 | 先 `concat` 后 `groupby` |
| 主表 + 附加属性，全保留主表 | `merge(how='left')` |
| 数据对账，看谁缺谁多 | `merge(how='outer')` |

## 跨语言类比

### SQL（必须类比）

```sql
-- merge 的本质就是 JOIN
SELECT * FROM users INNER JOIN orders ON users.user_id = orders.user_id;
-- = users.merge(orders, on='user_id', how='inner')

SELECT * FROM users LEFT JOIN orders ON users.user_id = orders.user_id;
-- = users.merge(orders, on='user_id', how='left')

SELECT * FROM users FULL OUTER JOIN orders ON users.user_id = orders.user_id;
-- = users.merge(orders, on='user_id', how='outer')

SELECT * FROM users UNION ALL SELECT * FROM more_users;
-- = pd.concat([users, more_users])
```

**记住这条对应**：以后看到 SQL 立刻能想到 Pandas 怎么写。

    orders.filter { $0.userId == user.id }

## 5 个最容易踩的陷阱

### 陷阱 1：忘了指定 `how`，默认 inner 把数据弄丢了

```python
# users 有 3 行，orders 有 4 行
result = users.merge(orders, on='user_id')
print(len(result))  # 可能只剩 3 行！丢失了未匹配的
```

**修复**：清楚自己要哪个 how，**默认 inner 经常不是你想要的**。处理"主表 + 附属"时通常应该用 `how='left'`。

### 陷阱 2：关联列有重复值，结果**行数爆炸**

```python
# users: 100 行
# orders: 每个用户平均 5 个订单 → 500 行
users.merge(orders, on='user_id')   # 结果会有 ~500 行，不是 100 行
```

**为什么**：merge 是**笛卡尔积式匹配**——左表 1 行 × 右表 3 行匹配 = 输出 3 行。

**反过来想**：你想保证"每个用户只 1 行"，要先 `orders.groupby('user_id').agg(...)` 把 orders 聚合掉。

### 陷阱 3：列名冲突（两边都有同名列但不是 key）

```python
users = pd.DataFrame({'user_id': [1, 2], 'name': ['Alice', 'Bob'], 'age': [25, 30]})
products = pd.DataFrame({'product_id': [1, 2], 'name': ['Phone', 'Laptop']})
```

两边都有 `name` 列但意思不同！merge 会自动加后缀：

```python
some_df.merge(another_df, on='id')
# 结果列名变成 name_x（左表）, name_y（右表）
```

**修复**：用 `suffixes` 显式指定：

```python
result = users.merge(products, on='id', suffixes=('_user', '_product'))
# 结果列名：name_user, name_product
```

### 陷阱 4：dtype 不一致导致匹配不上

```python
users['user_id']    # dtype: int64
orders['user_id']   # dtype: object (字符串！)

users.merge(orders, on='user_id')  # 匹配结果可能全是空
```

**修复**：merge 前先 `.astype(int)` 统一。**真实数据 CSV 读进来经常有这种坑**。

### 陷阱 5：NaN 不会匹配 NaN

```python
df1: user_id = [1, 2, NaN]
df2: user_id = [1, NaN, 3]

df1.merge(df2, on='user_id')  # NaN 不会和 NaN 配对！
```

NaN 在 Pandas 里**永远不等于自己**（`NaN != NaN`）。要让 NaN 配上需要 `df.fillna(...)` 先填值。

## 实战模板

### 模板 1：主表 + 附属表（最常见）

```python
# 主表：用户基本信息（保证不丢）
# 附属：每用户的最新订单
latest_orders = orders.sort_values('date').drop_duplicates('user_id', keep='last')
result = users.merge(latest_orders, on='user_id', how='left')
```

### 模板 2：多张表链式合并

```python
result = (users
          .merge(orders, on='user_id', how='left')
          .merge(products, on='product_id', how='left')
          .merge(addresses, on='user_id', how='left'))
```

### 模板 3：合并前先聚合（避免行数爆炸）

```python
# 错：直接 merge 会变成"每订单一行"
users.merge(orders, on='user_id')

# 对：先把订单聚合成每用户一行的统计，再 merge
user_stats = orders.groupby('user_id').agg({
    'amount': ['sum', 'mean', 'count']
})
users.merge(user_stats, on='user_id', how='left')
```

### 模板 4：数据对账（找差异）

```python
# 找"在 A 不在 B"的 id
result = a.merge(b, on='id', how='outer', indicator=True)
only_in_a = result[result['_merge'] == 'left_only']
only_in_b = result[result['_merge'] == 'right_only']
```

`indicator=True` 是个隐藏神器——加一列 `_merge` 标明每行来自哪边，对账场景必用。

## 速查表（按"我想做什么"）

| 我想做什么 | 写法 |
|---|---|
| 多个 DataFrame 上下叠 | `pd.concat([df1, df2, ...])` |
| 多个 DataFrame 左右贴 | `pd.concat([...], axis=1)` |
| 按列关联（默认交集） | `df1.merge(df2, on='key')` |
| 按列关联（保左表） | `df1.merge(df2, on='key', how='left')` |
| 按列关联（全保留） | `df1.merge(df2, on='key', how='outer')` |
| 关联列名不同 | `df1.merge(df2, left_on='a', right_on='b')` |
| 按 index 关联 | `df1.merge(df2, left_index=True, right_index=True)` |
| 同名列处理 | 加 `suffixes=('_x', '_y')` |
| 看每行来自哪边 | 加 `indicator=True` |
| concat 后重排 index | 加 `ignore_index=True` |

### 练习 4（陷阱）
```python
df1 = pd.DataFrame({'id': [1, 1, 2], 'x': [10, 11, 20]})    # 3 行
df2 = pd.DataFrame({'id': [1, 1, 2], 'y': [100, 101, 200]})  # 3 行

df1.merge(df2, on='id')
# 结果几行？
```

<details>
<summary>答案</summary>

**5 行**，不是 3 行！

id=1 在左有 2 行、在右有 2 行 → **2×2 = 4 行**
id=2 在左有 1 行、在右有 1 行 → **1×1 = 1 行**

总共 **5 行**——这就是"行数爆炸"陷阱。

```
   id   x    y
0   1  10  100
1   1  10  101
2   1  11  100
3   1  11  101
4   2  20  200
```
</details>
